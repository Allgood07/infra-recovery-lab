# Infra Recovery Lab

**Исправный `PING` не гарантирует, что клиент читает ранее подтверждённую запись.** После замены Valkey с исходным томом клиент читает точное значение, а с пустым томом получает `PONG`, но ключа нет. Фактические результаты, проверенная ревизия и статус GitHub Actions — в [коротком отчёте](reports/recovery.md).

## Повторить из чистого клона

Нужны Git, GNU Make, Node.js 22.18+ и npm, OpenTofu 1.9+ в `PATH`, запущенный локальный Docker Engine с CLI и доступным Unix-сокетом (на macOS подойдёт Docker Desktop). CI настроен на Node.js **22.23.5** и OpenTofu **1.13.10** — те же версии использовались для локального прогона в отчёте. Выберите локальный Docker-контекст, не удалённый Docker; если задан `DOCKER_HOST`, он тоже должен указывать на локальный Unix-сокет. Для загрузки npm-зависимостей, провайдера и образа нужен интернет. Стенд не требует секретов и не публикует порты.

```sh
git clone https://github.com/Allgood07/infra-recovery-lab.git
cd infra-recovery-lab
git checkout --detach 0699033b1a25ef3176692c46355744a33e101046
npm ci
```

Это SHA стенда из локального прогона в отчёте. Теперь выполните по очереди (для кода выхода сразу после каждой команды можно выполнить `echo $?`):

| Команда | Том после замены | Код и обязательные строки |
| --- | --- | --- |
| `make verify` | Исходный | `0`; `After: PONG; GET matched the exact pre-replacement value (...)` (в скобках время); `Cleanup OK: client, Valkey, network, all run volumes and local state absent`. |
| `make wrong-volume` | Новый пустой | Ненулевой (`2` у GNU Make); ровно `verify: After: PONG; GET=KEY_MISSING` и та же строка `Cleanup OK` — удалены оба тома этого прогона. |

Контрольная команда обязана завершиться ошибкой. Таймаут, сбой Docker/OpenTofu, другое значение, отсутствие подтверждения очистки или неожиданное прохождение не подтверждают контроль.

После `npm ci` можно отдельно выполнить `npm run typecheck` и `npm test`; Docker и OpenTofu для них не нужны.

## Что именно проверяется

[`main.tf`](main.tf) задаёт внутреннюю сеть Docker и AOF с `appendfsync always` на томе `/data`. Отдельный клиент из [`verify.ts`](verify.ts) подтверждает `SET` и сверяет исходный `GET` с синтетическим значением, которое хранит сам тест. Проверка удаляет только контейнер Valkey, фиксирует недоступность старого адреса и проверяет план замены. После запуска она сверяет новый ID и подключённый том; на новом соединении получает `PING` и читает тот же ключ, без повторной записи. Общий бюджет готовности и чтения — 30 секунд с момента запуска замены.

Очистка удаляет только ресурсы прогона. Если их отсутствие не подтверждено, команда завершается с ошибкой и сохраняет `.runs/<ID>/` для локального разбора. Образ и кеш провайдера могут остаться. Это проверка замены контейнера, а не потери диска или хоста, бэкапов или SLA.

Lab началась с этого стенда, а не с даты создания прежнего репозитория `Allgood07/test`.
