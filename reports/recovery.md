# Проверка восстановления Valkey

**Исправный `PING` не гарантирует чтение ранее подтверждённой записи.** После замены контейнера со старым томом клиент прочитал точное значение. На пустом томе клиент получил `PONG`, но ключ не нашёл.

**Локальный прогон из чистого HTTPS-клона:** `0699033b1a25ef3176692c46355744a33e101046`. macOS arm64, Docker Desktop 4.22.1 (Engine 24.0.5), GNU Make 3.81, Node.js 22.23.5, npm 10.9.9, OpenTofu 1.13.10, провайдер Docker 3.9.0, Valkey 8.1.6 Alpine (digest закреплён в `main.tf`).

| Команда | Код GNU Make | Фактическая строка результата |
| --- | --- | --- |
| `make verify` | `0` | `After: PONG; GET matched the exact pre-replacement value (0.76s / 30s)` |
| `make wrong-volume` | `2` | `verify: After: PONG; GET=KEY_MISSING` |

Оба прогона вывели `Cleanup OK: client, Valkey, network, all run volumes and local state absent`. После контроля не осталось ни исходного, ни пустого тома; списки ресурсов Docker по метке стенда были пусты, а в `.runs/` остался только кеш провайдера.

[`main.tf`](../main.tf) задаёт AOF с `appendfsync always` и выбор тома. [`verify.ts`](../verify.ts) проверяет новый контейнер и фактически подключённый том, затем сравнивает результат `GET` с маркером, сохранённым в тесте вне хранилища; `PING` сам по себе не критерий. Результат относится к замене контейнера при сохранении диска; не проверяет потерю диска или хоста, бэкапы, непрерывную доступность или SLA.

**GitHub Actions: не подтверждено.** [Workflow](../.github/workflows/recovery.yml) подготовлен, но run не запускался. Постоянная ссылка на run и SHA, который проверил раннер, пока отсутствуют. Чистый CI-раннер будет независимым окружением, а не отзывом другого инженера. Независимого ручного прогона по README ещё не было.
